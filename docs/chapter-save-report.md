# 第一章存档兼容与校验

存档仍使用 `{run, progress, settings}`。`run.chapter === 1` 编码为版本 2；无章节标记的旧旅程仍通过原有版本 1 校验和编码。`decodeSave` 不隐式迁移，以兼容既有工具；界面在读取、导入和恢复后调用 `migrateSave(data)`。

迁移保留队伍顺序、伙伴、经验、设置；旧战斗不映射为章节胜利，不凭空发放剧情物品。已结束但尚未结算的旧战斗按原规则结算一次，随后进入地图；已领奖励不再发放。旧选择界面保留选择状态。第一章的早期探索地点开放，不要求原玩家重做旧版队伍选择。成长记录中的旧伙伴也纳入所有权，避免保留经验却丢失伙伴。

版本 2 委托章节模型校验节点、物品、所有权和进化约束，并额外核验设置、成长所有权、战斗遭遇、双方队伍与成长、进化标记、胜负阶段、奖励明细与经验。战斗结果只允许首次胜利奖励或无奖励重战/失败；章节结算记录由模型保证幂等。普通自动保存拒绝覆盖损坏或未来版本；大小上限继续为 1,000,000 字符。

原有滚动备份机制和恢复失败回滚保持兼容。首次 v1→v2 写入前，额外将原文写入 `shanhai-save-v1-original`；此操作失败则不覆盖主存档。即使滚动备份含有必须保护的损坏/未来版本原文，两份原文也同时保留。`readLegacyOriginal(storage)` 返回 `{raw,error}`，供界面「导出迁移前存档」使用；后续自动保存或显式新旅程不覆盖此原始副本。迁移后的自动保存保留原 v1 备份，不在下一次自动保存时将其覆盖。显式导入/新旅程仍通过 `replaceSave`，保留被替换原文。存档不是防作弊签名：合法完整状态可由用户编辑，本地校验主要避免损坏、错配与重复结算。

验证：`node --test tests/chapter-save.test.js tests/save.test.js` 共 19/19 通过（9 项章节存档测试、10 项原版回归），覆盖所有旧阶段迁移、v2 战斗及首次/重复奖励、非法状态、原文保留与存储失败。单元测试不等同于浏览器完整试玩；浏览器集成由章节 QA 单独验证。
