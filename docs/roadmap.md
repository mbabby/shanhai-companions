# 开发阶段与验收

阶段范围随已确认设计调整。第一章范围已获确认，实现与验收分别记录；完整产品的多人和长期运营系统不属于本章。

| 阶段 | 范围 | 验收标准 |
| --- | --- | --- |
| 0 设计 | 玩家身份、玩法、六种异兽候选、成长视觉方向、首版范围 | 关键玩法确认；规格可执行；标明原典与原创内容 |
| 1 战斗 | 六种异兽配置、三只组队、技能、换兽、状态、敌方 AI | 至少两种阵容可胜；战术选择有效；规则测试覆盖结算边界 |
| 2 探索捕捉 | 八地点节点地图、环境准备、习性结契、六兽图鉴、三兽队伍与后备 | 可完成探索到组队流程；捕捉条件清楚；失败可恢复 |
| 3 完整试玩 | 轻量升级、三种明确选择的进化、三场关键战斗、结局、本地存档与旧版迁移 | 三种初始选择可从新游戏推进到结局；刷新续玩及导出导入有效；重战不重复奖励 |
| 4 表现体验 | 原创美术、动效、音效、引导、触屏与性能优化 | 浏览器手机视口无阻塞性问题；真机与新玩家独立完成另作外部验证 |
| 5 外部测试 | 邀请 10–20 人，记录完成、卡点与阵容，修复问题 | 用实际反馈决定扩展方向；不以邀请人数代替验证结果 |

## 当前范围外

账号、云存档、多人 PVP、付费系统、大规模地图和批量角色制作，待试玩验证后再排期。没有承诺上线日期或阶段工期。

## 进度定义

- 未开始：无实现或验证产物。
- 进行中：已有工作产物，尚未满足验收。
- 待验收：产物及验证记录可供评审。
- 完成：满足明确验收标准，已提交并同步 GitHub。
